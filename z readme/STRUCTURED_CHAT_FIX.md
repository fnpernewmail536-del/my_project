## 開催年による除外

年条件と「他の解放割合より優先する」は、1つの除外条件にまとめて扱います。除外は割合計算の前に全レアリティへ適用し、除外された既存所持キャラは削除しません。個別削除キャラも割合の母集団から除きます。

元データにはコラボ最終開催年の履歴がありません。そのため、更新済み注文書には現在 **開催履歴の確認待ち1件** が残ります。履歴が不足している状態では、解放割合の対象数・所持目標数を仮計算しません。確認待ちの文だけを消して、不完全な依頼を実行することはありません。年条件を残す場合は確認済みの除外対象を指定します。年条件が不要な場合は、新しい注文書を読み込んでから「開催年の条件を外して再解析」を選べます。旧下書きは全文再送が必要です。

対応する入力方法は次の2つです。

- 除外シリーズを明示する場合：注文書の年条件と年優先文の2行を、`除外コラボ:シリーズの正式名1、シリーズの正式名2` に置き換えます。名前は実際の所属定義と照合します。
- 年条件を維持する場合：メタデータの collaboration_history、または local_chat/collaboration_history.json に、基準日 as_of と series ごとの last_held_year・source を登録します。series のキーは実際のコラボ所属定義の id です。基準日は実行する当日、確認元は空欄不可です。履歴の一部不足・未所属キャラ・確認後の除外対象変更があれば停止します。

開催年やシリーズ名を推測して埋める機能はありません。所属が複数あるキャラは、確認済みの最も新しい開催年で判定します。
