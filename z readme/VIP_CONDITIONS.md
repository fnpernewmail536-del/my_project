# VIP選択画面の条件付き指定

既存の「代行」「アカウント作成」画面に、ローカル版の条件付き処理を追加します。
「範囲指定・レア度別レベル・除外（追加）」内の「条件付き指定」から、変更する項目、
対象、計算方法、変更前の値で判定する条件を追加してください。

## 指定できる内容

- 通貨・チケット：固定値、保持、上限、加算・減算、倍率と切り捨て、範囲抽選、最低値。
- キャラ：基本Lv・＋値・解放状態・第3形態までの解放。レア度、コラボ／通常、
  コラボ名、正式名・形態名・No.番号、ちび／大狂乱／特急系で対象を絞り込めます。
- 条件：現在値が未満／以下／同値／異値／以上／超過、偶数・奇数。複数条件はすべて満たす対象です。
- アイテム：種類ごとの固定値・加算・倍率・範囲と、個別種類の保持。
- 本能：実装済み本能だけのMAX、移動速度本能の保持、キャラごとの保持。
- 本能玉：ランク選択と現在個数の条件。装着済み本能玉を変更する操作はありません。
- お宝：章の選択、普通のお宝の保持、クリア済みステージだけの変更。
- レジェンド：旧／真／零の冠数、星4の保持、最終ステージの1つ前まで、現在のクリア冠数に応じた進行。
- 隊員：既存隊員を保持して10体まで補充、既存レジェンドを保持して他の隊員だけ変更。
- 施設、オトート、神社、ガマトトLv、エラーキャラ削除。

例ボタンから「通常超激・Lv30未満だけ50」「レアの＋20未満だけ＋30」
「日本編の普通のお宝を保持」を追加できます。

すべての条件・計算は変更前のセーブを基準にします。同じ値を二重に加算せず、
具体的なキャラ・種類の指定を全体指定より優先します。同じ対象では後の指定が優先です。
「現在値を減らさない」は全体、または各指定に設定できます。

## 実行と保持

条件付き指定を使う場合は、通常の一括選択・個別キャラ選択・従来の範囲指定を解除してください。
固定値も条件付き欄へ追加できます。両方式が混ざる入力は実行前に拒否します。

対象名、ゲーム定義、入力形式、上限は既存VIP権限の確認後、引き継ぎ取得前に検証します。
既存の実行ワーカー、試用VIP予約、バックアップ、復旧用コードを使います。
編成10枠・使用形態・お気に入り・並び順を保持し、適用後はBCSFEで保存・再読込して
変更した領域と版数を検証します。不一致があれば最終アップロードを止めます。

## 対応範囲

自然文を入力するチャットは増設しません。既存選択画面の条件入力を使用します。
現在開催中のコラボ、属性・特性での自動選別、第4形態の条件判定には対応しません。
開催中のコラボや属性条件は、確認したコラボ名・キャラ名・No.番号を指定してください。
「降臨」全体の系統を推測せず、具体的なイベント名を指定してください。

## 検証・適用

- Pythonの既存・追加テスト48件成功。
- 実際のVIPテンプレートとJavaScriptをDOM上で実行し、条件入力、送信、
  プリセット保存／復元、タブの独立、不正値、方式の混在拒否、確認取消を検証。
- 合成JPセーブをBCSFEで保存・再読込し、条件分岐、保持、冠、隊員、元の版数を検証。
- 実アカウント引き継ぎ・ゲーム起動は未実施。

更新ファイルはルートのmain13.py、HTML/vip.html、static/js/vip-form-extras.js、
vip_conditionsフォルダーです。既存の.env・DB・BGM・背景を保持してください。
GitHubへ反映してRenderを再デプロイした後、Ctrl＋F5で画面を再読込します。
