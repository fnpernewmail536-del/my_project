# Renderの代行チャット

VIP選択画面の「代行チャット」または `/chat/` から開きます。
同じFlaskアプリ（wsgi:app）を使い、別ポート・追加プロセス・追加APIサービスは不要です。
サイトのVIP契約状態を毎回確認します。試用回数の予約・実行枠・APIキー・受付ID・ジョブ所有権・
バックアップ・復旧用コード発行は既存の代行処理を共用します。

依頼を入力 → 引き継ぎコードと認証番号を項目名付きで入力 → 内容を確認 →「確認して実行」。
確認前にゲームの引き継ぎは取得しません。定義不足は実行受付前に停止します。
同じ送信IDの再送は同じ受付を返し、表示内容が変わった古い確認IDは受け付けません。

ローカル版の種類別アイテム・個別育成/解放・通常ガチャ限定＋値・プレイ時間・隊員構成・
塔/地底迷宮・明示候補によるランク/所持数調整を含みます。
プレイ日数の変更は未対応。「その他の隊員」はクラスの明示が必要です。
キャラ・ステージ・上限は取得できた定義を使用し、未確認の新キャラを推測しません。

入力途中の依頼と認証情報はサーバーメモリのみで保持します（20分、最大256セッション）。
Cookieにコードを入れません。Renderのスリープ・再起動時は入力し直してください。
受付済みジョブは既存ジョブDBに保存され、自動再実行しません。履歴は同じブラウザーで開きます。
既存Render設定の1 worker/gthreadを維持してください。複数worker用の共有ドラフトストアは未実装です。
64番は既存の変更前スナップショット/復旧処理を利用します。ローカルPCへの別ファイル保存ではありません。

## 検証

Pythonの既存チャット259件と公開接続10件、クライアントフロー5件を確認。
公開接続ではVIP拒否・CSRF・入力サイズ・確認前停止・古い確認・二重送信・ジョブ所有権・
既存VIP回数予約/受付・スレッド間の編集設定分離・ネイティブ保存/再読込を検証。
実アカウントの引き継ぎ通信・ゲーム端末起動は未実施です。
